## Key facts

- Collection contents (title and blurb as shown) form a map of the atproto spaces ecosystem:
  - The Atproto Spaces Alpha is Live (atproto.com): spaces, formerly known as the permissioned data protocol, is a new atproto extension for non-public data, with the alpha officially open.
  - Atproto spaces alpha updates (Discourse, discourse.atmosphere.community): states that the alpha was launched, that specification and implementation will iterate with likely breaking changes to the PDS distribution, the Bluesky-hosted alpha PDS and the alpha SDKs, and that releases are planned for Thursdays.
  - Reintroducing Spaces (dholms.leaflet.pub): re-motivates the design of spaces as the new primitive for non-public data.
  - Proposal for Atmosphere Groups standard on atproto spaces (tangled.org, opensocial.group/proposal).
  - The Arbiter series by Zicklag (Progress Reports 1 to 4): a general-purpose, interoperable group membership service, since the permissioned data proposal has membership but leaves orchestration to the app; later reports cover a policy-based arbiter prototype, a draft interoperable lexicon for group servers, and using permission sets to create virtual custom scopes.
  - Habitat road-to-release posts (building [at] habitat): 01 simplespace pre-implementation, 02 sap (a package to keep permissioned data in sync for apps), 03 ReBAC on spaces, 04 Chalk, 05 adopting opensocial, 06 commenting via space inheritance, plus a post on permission spaces for organizations.
  - Nick Gerakines posts: Permissioned Data: Space Access (how space configuration decides which people and which apps get credentials) and Permissioned Data Shapes: Feeds (a feed that includes space content must become a syncer, keep a live model of who can see what, and serve a different skeleton to every viewer).
  - Permissioned Spaces Made Pretty (a Lexidraw drawing by essentialrandom.bsky.social).
- One card includes a user note from fig (aka:[phil]) criticising the atproto spaces repo export: a giant index block feels odd, may put a low and hard cap on the number of records in a space, and the key ordering seems unfortunate. This is an opinion by that user, not a spec statement.
- Terms seen across the collection: simplespace, ReBAC, space inheritance, permission sets, group servers, arbiter, opensocial.
