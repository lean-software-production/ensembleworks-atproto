## Key facts

- Context: plugins can spawn many hidden worker threads with `bb.sdk.threads.spawn`, but `threads.stop` did nothing for an idle thread at the time of filing.
- Problems listed: the server does not dispatch stop for an idle thread; `threads.archive` eventually releases the process but can take several minutes; repeated hidden-thread runs can retain many agent processes in one reused environment and exhaust host memory; a requested turn can stay active when `turn/started` never arrives.
- Proposal: extend the existing stop contract instead of adding a separate eviction concept. `threads.stop(threadId)` should release active, starting, idle, error, archived and stuck runtimes; be idempotent when no runtime is loaded; preserve the thread, events, environment and future resume behaviour; return only after the host completes the runtime release.
- Archive stays a separate organisation and retention action. Plugins should archive a finished hidden worker when appropriate, then call stop in a `finally` block.
- Keep the existing `bb thread stop <thread-id>` CLI surface and update its help. Bump the daemon protocol version because stop changes its host-wire meaning.
- Acceptance criteria (6): prompt release of an idle hidden thread agent process; same call reclaims active, starting and stuck runtimes; a later turn can resume the preserved thread; repeated stop calls succeed; SDK, CLI guide, plugin API guide and skills describe the same contract; hidden-thread examples clean up in a `finally` block.
- Relevance: shows the bb plugin SDK surface (`bb.sdk.threads`) and thread lifecycle semantics (stop versus archive, preserved events and environment on resume) that an ATProto session-sharing plugin would build on.
